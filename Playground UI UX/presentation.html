UI/UX Audit & Direction · 2026-06-07

Dexterpreter

An offline, on-device Spanish transcription + translation app — reviewed from source and the live dev server. Strong glass bones, but the screens users live in clash with the brand, the core waveform is faked, and the layout ignores its own target device. Here is the three-move plan to fix it.

React 19 · Vite · Tailwind v4 On-device · Transformers.js Capacitor · Android tablet Live-reviewed @ 375px & 1280px

Brief diagnosis

A precision tablet tool wearing a phone-demo skin

The product is sound and the onboarding is genuinely nice. Four problems hold the experience back — three are visible, one is a quiet honesty bug in the most-used widget.

Honesty bug

The waveform is fake

AudioCanvas.tsx:29-40 builds a Math.random() shape, plus three neon sine "ribbons". The user scrubs and edits against a decoration — yet real PCM is already decoded for silence detection.

Consistency

Two competing palettes

Shell = azure glass. But the editor, translation & waveform still run on the old indigo + slate-700/950 palette. The screens users spend the most time in fight the brand.

Layout

Ignores its own device

Target is a 14.6″ tablet. Live inspect: <main> is max-width:none; modals pinned to max-w-sm. ~60–70% of the screen is wasted and Spanish/English never sit side by side.

Accessibility

Too small, too low-contrast

Saturated with text-[10px]/[11px] and even text-[8px], much of it slate-500 on near-black (header subtitle verified at 10px). Plus a Tab-key hijack that breaks focus order.

Recommendations

The top 3 moves

🥇

Render the real waveform

Concept #1 · Effort: Med Impact: High

Why it wins: The waveform is the center of the core loop (scrub → find → edit → loop) and today it's decorative noise. Fixing it turns the most-touched element into the app's most useful instrument and removes a credibility risk no other polish can offset. The real PCM is already decoded for silence detection — the hard part is done. The other moves make the app nicer; this one makes its core honest and functional.

First pass

  • Peak envelope (600–1000 buckets) from existing decoded PCM
  • Real bars + dim silence gaps from vad.ts
  • Single azure played/unplayed split; remove 3 neon ribbons
  • Cache peaks on the project record for instant reopen

Defer

  • Zoomable / pinch waveform
  • Per-word amplitude alignment
  • Color-by-confidence overlay

Files

AudioCanvas.tsx · App.tsx · reuse lib/audio.ts + lib/vad.ts · cache on lib/db.ts

Before → After

Before — fake

  • Random walk; same shape for every file
  • 3 rainbow sine ribbons (off-brand)
  • No relationship to speech or silence

After — real

  • True peak envelope from decoded PCM
  • Silence gaps visible at a glance
  • One azure played/unplayed split — on brand

Acceptance

  • Bars derive from real samples (transient + silence visibly distinct on a known clip)
  • Silences rendered as gaps; played/unplayed uses the azure token
  • No Math.random() amplitudes; rainbow ribbons removed
  • Peaks cached so reopened projects render instantly
🥈

Responsive two-pane bilingual layout

Concept #3 · Effort: Med–High Impact: High

Why it wins: It aligns the app with its actual device (14.6″ tablet) and its actual job (read Spanish against English). It reclaims 60–70% of wasted screen and delivers the one view a bilingual user most wants but can't get today. Higher ceiling than the cheap polish items, and uniquely tied to the hardware it ships on.

  • Right pane sticky English, scroll active segment into view

  • Per-column max-w for readable line length

  • Interleaved ES/EN "read" mode
  • Drag-to-resize panes
  • App.tsx grid · TranslationPanel.tsx sticky+sync · minor TranscriptView.tsx

  • At ≥1024px, Spanish + matching English visible together, no vertical hunting
  • Active sentence/segment highlights in both panes
  • Column line length capped; wasted empty space gone
  • Phone layout unchanged; no horizontal scroll at any breakpoint
🥉

Legibility, contrast & a11y pass + design-system unify

Concepts #4 & #2 (bundled) · Effort: Low–Med Impact: Med–High

Why it wins: The cheapest broad quality lift and the only top pick that touches every screen. It fixes genuine usability harm (8–11px low-contrast text at tablet distance, sub-44px targets) and a real keyboard-a11y bug — and because the same sweep introduces color tokens, it also closes the indigo/azure split. Two of the four headline problems gone in one low-risk, style-only pass. Highest maintainability payoff for least effort.

First pass

  • Type scale: body 14 / secondary 12 / micro 11 floor (retire 8 & 10px)
  • Informational text → ≥4.5:1 contrast token
  • Icon buttons padded to ≥44×44
  • Scope the Tab shortcut so native focus order survives
  • Semantic color tokens; refactor editor/translation/waveform off indigo + raw slate

Defer / Files

  • Full light theme; density toggle
  • index.css (tokens+scale)
  • CaptionEditor · TranslationPanel · AudioCanvas
  • App.tsx (key handler, micro labels) · CaptionExport.tsx (8px labels)

Acceptance

  • No text below 11px; informational text passes AA (4.5:1)
  • All interactive targets ≥44×44
  • Tab no longer breaks page focus order; consistent focus ring
  • Zero indigo / raw slate-700|950 utilities in components; one accent = "active"

Risks & tradeoffs

What to watch

Performance on long files

Real waveform + browsable editor must use fixed-bucket envelopes and count-based virtualization to stay O(n).

Don't regress the phone

Every layout change must keep the <md single-column intact — the app still ships to phones.

Honesty in copy

Uncertainty cues and the stepper must not over-claim: flag "spots to check", show only stages that actually run.

GPU cost & motion

Heavy backdrop-filter on a big tablet is already costly — drop the animated ribbons, keep prefers-reduced-motion honored.

Discoverability vs. tidiness

Collapsing power tools (#5) can hide features — keep them secondary-but-present and remember open state.

APK / release discipline

Per project rule, bundle these UI changes into one rebuilt signed APK + refreshed GitHub Release rather than many.

Validation checklist

How we'll know it worked

  • axe/Lighthouse a11y: AA contrast, target sizes, focus order all pass
  • Known-clip waveform test — transient + silence visible
  • Tablet (≥1024) shows bilingual side-by-side; phone unchanged; no horizontal scroll
  • One accent = "active" across all surfaces; no indigo remnants
  • Every export/save shows visible confirmation; no window.confirm
  • New-session activation (reaches a transcript) measurably up after the sample clip
  • Unit tests green (npm test); clean npm run build

Next step

Start here

Begin Wave 1. Add semantic color + type tokens to index.css, then refactor CaptionEditor, TranslationPanel and AudioCanvas onto them — bumping every sub-12px size, padding icon buttons to 44px, and scoping the Tab shortcut.

Low-risk and style-only, it closes two of the four headline problems and lays the token foundation that the real waveform (#1) and the two-pane layout (#3) both build on.
